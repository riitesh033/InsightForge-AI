# Core Data Workflow Repair

## Scope

Repaired and tested the existing dataset upload, profiling, analysis, AI chat,
cleaning, and PDF report workflows without changing their API shape or
introducing a selectable cleaning strategy that the application does not
currently provide.

## Deterministic test fixtures

The `workflow_files` pytest fixture in `backend/tests/conftest.py` supplies
in-memory file payloads for:

| Fixture | Deterministic data |
| --- | --- |
| `normal.csv` | 3 records with ID, age, and salary |
| `missing.csv` | Numeric and categorical missing values |
| `duplicates.csv` | One duplicate row |
| `outliers.csv` | Numeric series containing a high outlier |
| `categorical.csv` | Repeated categorical values |
| `mixed.csv` | A column with numeric and textual values |
| `empty.csv` | Header-only, zero-row CSV |
| `one-row.csv` | Single record |
| `wide.csv` | 120-column CSV |
| `workbook.xlsx` | Three-row workbook generated by pandas/openpyxl |
| `invalid-empty.csv` | Zero-byte malformed CSV for the parser error case |

Files are sent to the upload route through the test client; XLSX bytes are
generated in memory. The suite does not create persistent fixture data.

## Repairs

- Upload now stores a basename-only original filename even when a client sends
  a Windows- or POSIX-style path. Storage filenames remain generated UUID names.
- The analysis PDF route now maps missing files, invalid source data, and
  unexpected report failures to safe HTTP errors while preserving server-side
  logging. This aligns it with the separate reports PDF route.
- The AI provider router rejects whitespace-only responses and continues its
  existing provider fallback sequence. The chat service also converts a blank
  answer to its existing safe unavailable response.
- No frontend code or API contract was changed.

## Test coverage

`backend/tests/test_data_workflow.py` covers:

- Upload authentication, extension and size validation, malformed/empty files,
  path-safe filenames, UUID storage names, and persistence of dataset/analysis.
- Persisted row/column/memory counts, missing values, duplicate counts,
  statistics, numerical correlations, outlier counts, and categorical frequency.
- Analysis response shape and dataset ownership enforcement.
- Cleaning preview, automatic median/mode filling, duplicate removal,
  whitespace normalization, apply/download behavior, original-file
  immutability, and missing-source/download errors. Dropping missing rows is
  not an existing cleaning option and was not invented as part of this repair.
- Chat authentication and dataset ownership, session/message persistence,
  provider failure and empty-answer fallbacks, and safe response text.
- Mocked AI provider fallback and failure for malformed, timed-out, and empty
  responses. No live AI provider is called.
- PDF generation, content type/signature, missing-source handling, and report
  dataset ownership. PDF generation is tested without requiring AI-generated
  findings.

There is no frontend test script or established frontend test runner in
`frontend/package.json`; no new test framework was added. Frontend lint and
production build were run as regression checks.

| `npm run lint` | PASS: 0 errors | 3 existing React Fast Refresh warnings |
| `npm run build` | PASS | Vite reports the existing large-chunk warning |

The pytest fixture uses an in-memory SQLite database. The application lifespan
also attempted its configured PostgreSQL migration bootstrap; PostgreSQL at
`localhost:5432` refused the connection. That bootstrap failure is logged by
the app, but test database dependencies are overridden to SQLite and all 95
tests completed successfully. Consequently, no PostgreSQL-backed execution
result is claimed.

The final complete test run had no failing tests. It reported the existing
Starlette/httpx TestClient deprecation warning and SQLAlchemy's use of
`datetime.utcnow()` in test-created records. These warnings were not suppressed
or changed as they are outside the data-workflow changes.

## External/manual verification not performed

- PostgreSQL migrations and workflow persistence require a running PostgreSQL
  instance; not tested because the configured local server was unavailable.
- Gemini, OpenRouter, and Ollama were mocked. Live provider credentials,
  connectivity, and provider-specific response behavior remain unverified.
- Stripe is not part of this workflow test run.
- Browser-driven frontend behavior was not tested; no frontend test harness is
  configured.
